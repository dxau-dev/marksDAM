# Mark’s DAM
## System Overview 
A command line utility that recursively scans a directory tree, finds images and submits them to OpenAI for **batch** processing. 
It has two modes:
* Submit and
* Retieve 
Use the OpenAI Go SDK at github.com/openai/openai-go
The images will be provided via a fully qualified URL to an image file.
## System Structure
Each major sub component needs to be its own package. 
### The `config` Package
The config package exists. All configuration variables need to be accessed through the corresponding `GetConfigVar()` function. 
### Database Functionality
There are two relevant packages. 
* `dbOpen` which returns the relevant, initialised `*sql.DB` struct. All database access is through the `db` returned by `func OpenDB()`. Also ensure that `func CloseDB` is called deferred immediately after instantiating the db access.
* The package `dbAccess` is generated by `sqlc`. The query and schema files are called `query.sql` and `schema.sql` respectively. These files are in the `sql/` directory. All schema changes and queries are to be done via `sqlc`
### File System Utility Functions
The system includes the package `github.com/dxau-dev/fileUtilities`. All file and directory related functions are to be performed using these functions. 
### Dates
If any dates are required to be stored in the database, then they **MUST** be stored in UTC format. Use the package `github.com/dxau-dev/dateUtilities` for date parsing and conversion from local to UTC **before** saving dates to the database, and **after** retrieving dates from the database. 
## Functionality 
The system needs:
* The ability to process command line switches 
* The ability to retrieve configuration options via a TOML file
* Data storage is in a SQLite database 
	* The TOML file and the db are located in the same directory. 
* OpenAI API key set in an environment variable OPENAI_API_KEY
## Command Line Switches Needed
* **submit** This mode scans the file system, stores file information in the database and uses the id from the record as the custom_id field required by OpenAI. It submits the batch to OpenAI for processing 
* **retrieve** This mode polls OpenAI when run. If the batch is finished, it retrieves the results and updates the database. 
* **setup** this mode has a parameter specifying the **relative** path of the database and TOML file directory. Relative to the current directory that the command is run from. It creates and initialises both the TOML file and the database. The database creation / initialisation function is `dbAccess.CreateDB()`. The TOML file initialisation code needs to be created. 
* **config** this switch has a parameter of the directory location for the database and TOML file. This is a required parameter for submit and retrieve modes. 
## TOML Configuration Options
These options are returned by the relevant `config.GetConfigVar()` function. If the TOML files doesn’t specify the value, then the default is used. 

* webHost // The host name of the server that is submitted to OpenAI as the `image_url`
* sImageExtensions // A slice of file extensions for the files that will be submitted.
* dbPath // The database and TOML file path

* model // Which OpenAI model is used
* detail // The `detail` parameter tells the model what level of detail to use when processing and understanding the image 
If, on examining the API, further configuration options are needed then add them as required. 
## Submit Mode
Submit mode recursively scans the directory from where the command is run. It needs to update the database and retrieve the id as the API requires a `custom_id`. The field `image_file.file` is to hold the path of the image file, **from where the command is run**. For example, if the command is run in the directory `/var/www/files` and there is an image called `mycat.jpg` in the following sub directory: `/var/www/files/job-10/animals/mycat.jpg` then the string in the database will be `job-10/animals/mycat.jpg`. 

The system will need to create the json file and submit it to OpenAI. Once the submission has been accepted, update the database with the returned data. (**NOTE** This will require creating the relevant tables in the database.)
## Retrieve Mode
This mode polls the API and, when the batch is ready, downloads the results and populates the database.
